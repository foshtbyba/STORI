# MS TEAM

Учёт арбитражной команды: профит баеров по дням, расходники, зарплата по лесенке
ставок, база офферов и рейтинг-гора.

## Запуск

```bash
npm install
cp .env.example .env      # поправь AUTH_SECRET
npm run db:reset          # создаёт базу и заливает демо-данные
npm run dev               # http://localhost:3000
```

**Демо-вход:** `admin@ms.team` / `stori`.
Баеры — `nomad@ms.team`, `sko@ms.team`, `luna@ms.team`, `viper@ms.team`,
`artem@ms.team`, пароль тот же.

## Как считаются деньги

Всё хранится в **целых центах USD** — ни одна сумма не лежит во float, поэтому
итоги не разъезжаются. Округление до круглых чисел живёт только в отображении
(`src/lib/money.ts`): десятки до $1 000, сотни до $100 000, тысячи выше. Итог
всегда округляется от точной суммы, а не от уже округлённых строк.

День считается так:

```
расход с комиссией = спенд × (1 + комиссия платёжки)
чистый профит      = доход − расход с комиссией
```

Ставка комиссии **снимается в момент записи** и хранится в самой строке дня, так
что смена тарифа платёжки не переписывает закрытые периоды. Если в строке указана
точная списанная сумма — она важнее расчётной.

Зарплата (`src/lib/salary.ts`):

```
база   = профит − расходники баера   (если они на него списываются)
ставка = процент достигнутого порога, применяется ко ВСЕЙ базе
ЗП     = база × ставка + фикс + бонусы
```

Лесенка не маржинальная — поэтому у порога пара сотен профита меняет выплату на
тысячи. Экран зарплаты показывает эти «мёртвые зоны» отдельно.

## Что где лежит

| Путь | Что это |
|---|---|
| `prisma/schema.prisma` | схема; SQLite для разработки, меняется на Postgres одной строкой |
| `src/lib/money.ts` | центы, округление, гросс-ап комиссии |
| `src/lib/salary.ts` | лесенка ставок и расчёт выплаты |
| `src/lib/import.ts` | парсер строк вида `sko 30800 - 20900 + 21800` |
| `src/lib/terrain.ts` | генератор рельефа горы — все параметры в `DEFAULT_TERRAIN` |
| `src/lib/queries.ts` | агрегаты периода за один проход |
| `src/components/Mountain.tsx` | отрисовка горы, компаса, пинов и маршрута |
| `src/app/actions/` | серверные действия: дни, период, справочники |

### Правка горы

Форма горы задаётся объектом `DEFAULT_TERRAIN` в `src/lib/terrain.ts`: ракурс
(`squash`), размеры (`radius`, `height`), плотность изолиний (`levels`,
`indexEvery`), характер рельефа (`octaves`, `warp`, `domeSigma`, `shoulders`).
Ничего больше трогать не нужно — пины и маршруты сами встают на новую поверхность,
потому что позиции берутся запросом «где склон на такой высоте».

Рельеф детерминированный и не зависит от данных, поэтому строится один раз и
кешируется по конфигу.

## Роли

- **ADMIN** — всё, включая закрытие периода и справочники.
- **LEAD** — видит команду, вводит дни за других, не закрывает период.
- **BUYER** — видит и правит только себя; попытка записать чужой день отклоняется
  на сервере, а не в интерфейсе.

## Периоды

Период — календарный месяц. Закрытие фиксирует выплаты в таблицу `Payout` по
текущим ставкам и курсу и блокирует правки дней. Открыть обратно может админ —
и это, как и любая запись в денежную строку, попадает в `AuditLog`.

## Боевой запуск

Локально живёт SQLite (один файл, ничего ставить не надо). На сервере —
Postgres: команда работает одновременно, а SQLite этого не любит.

### Вариант A. Свой сервер, Docker (рекомендую)

Данные команды остаются у тебя, всё поднимается тремя контейнерами:
приложение, Postgres и Caddy, который сам выпускает HTTPS-сертификат.

**Требования к VPS:** виртуализация **KVM** (на OpenVZ Docker не заводится),
от 2 ГБ памяти, 20 ГБ диска, Ubuntu 22.04 или 24.04.

```bash
# на сервере, от root
apt update && apt install -y git curl
git clone -b claude/profit-tracking-dashboard-ulxq52 <репозиторий> ms-team
cd ms-team
bash scripts/bootstrap.sh
```

`bootstrap.sh` ставит Docker, генерирует секреты в `.env`, определяет домен
(из внешнего IP через `sslip.io`, либо передай свой аргументом), переключает
Prisma на Postgres и поднимает контейнеры. Повторный запуск безопасен: `.env`
не перезаписывается, секреты не перегенерируются.

Первая сборка занимает 3–5 минут. Миграции накатываются при старте контейнера.

Дальше — первый администратор:

```bash
docker compose exec app npx tsx scripts/create-user.ts admin@ms.team "Админ" ADMIN
```

#### Пока нет домена

HTTPS обязателен: кука сессии помечена `secure`, по обычному http браузер её
просто не сохранит и вход не сработает. Сертификат на голый IP не выпускают,
но домен покупать не обязательно — есть сервисы вроде `sslip.io`, которые
превращают IP в имя:

```
DOMAIN=203-0-113-45.sslip.io      # для IP 203.0.113.45
```

Ничего настраивать не нужно, DNS уже отвечает, Caddy выпустит на это имя
обычный сертификат Let's Encrypt.

#### Свой домен

1. У регистратора домена заведи A-запись на IP сервера — саму зону и `www`:

   ```
   @     A    185.237.218.74
   www   A    185.237.218.74
   ```

   Прокси (оранжевое облако Cloudflare и подобное) на время выпуска
   сертификата лучше выключить: Let's Encrypt должен достучаться до сервера
   по 80 порту напрямую.

2. Дождись, пока имя начнёт резолвиться: `dig +short твойдомен` должен
   вернуть тот же IP. Обычно это минуты, но бывает и до часа.

3. На сервере поменяй домен в `.env` и подними заново:

   ```bash
   cd ~/msteam
   sed -i 's/^DOMAIN=.*/DOMAIN=твойдомен, www.твойдомен/' .env
   docker compose up -d
   docker compose logs -f caddy      # видно выпуск сертификата
   ```

`DOMAIN` можно перечислять через запятую — Caddy возьмёт сертификат на каждое
имя. Старое имя после этого перестанет отвечать: оставь его в списке, если
нужно, чтобы работали оба. Никакой пересборки образа не требуется, база и
статистика не трогаются.

### Вариант B. Vercel + внешний Postgres

Быстрее, но база и приложение живут у чужих провайдеров.

1. Заведи базу в Neon или Supabase, скопируй строку подключения.
2. Импортируй репозиторий в Vercel.
3. В переменных окружения задай `DATABASE_URL` и `AUTH_SECRET`.
4. Локально: `npm run use:postgres`, закоммить изменённую схему.
5. После первого деплоя один раз накати миграции: `npm run db:migrate`
   с боевым `DATABASE_URL` в окружении.

### Первые пользователи

Демо-сид (`db:reset`) заливает выдуманный месяц — на боевой базе его запускать
не надо. Аккаунты заводятся по одному:

```bash
npx tsx scripts/create-user.ts admin@ms.team "Админ" ADMIN
npx tsx scripts/create-user.ts sko@ms.team "SKO" BUYER SKO
```

Скрипт печатает сгенерированный пароль один раз — передай его лично. Сменить:
`npx tsx scripts/set-password.ts sko@ms.team` (можно вторым аргументом задать свой).

Сразу после первого администратора заведи справочники — платёжки, типы
расходников и лесенку ставок. Без них не из чего выбирать при списании:

```bash
npx tsx scripts/init-catalog.ts
```

Скрипт идемпотентный: существующее не трогает, запускать можно повторно.

### Обновление кода

`.env` в архив не попадает, поэтому распаковка поверх не затирает секреты:

```bash
cd ~/ms-team
unzip -o ~/ms-team.zip -j -d /tmp/upd && rm -rf /tmp/upd   # проверка, что архив цел
unzip -o ~/ms-team.zip                                      # распаковать поверх
docker compose up -d --build
```

База живёт в томе Docker и переживает пересборку.

### Что не забыть

- **`AUTH_SECRET`** — длинная случайная строка. Сменишь — разлогинятся все.
- **Бэкапы.** `docker compose exec db pg_dump -U msteam msteam | gzip > backup.sql.gz`
  по расписанию. Здесь лежат деньги команды, потерять базу нельзя.
- **HTTPS обязателен** — сессия ездит в куке, по http её видно.
- Первым делом заведи админа и удали демо-данные, если случайно засеял.
