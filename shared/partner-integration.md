# Как добавить новую партнёрку в конструктор

Партнёрка (CRM приёма заказов) в конструкторе описывается одним объектом + общим движком
отправки заказа. Чтобы её добавить, нужно понять, **как её API принимает лид**.

Есть два пути — первый быстрее и надёжнее.

---

## Путь 1 (лучший): прислать рабочий сэмпл ленда

Пришли **любой готовый `index.html` от этой партнёрки, который реально отправляет заказы**
(с их скриптом отправки внутри), плюс свои `ref` и `api_key`. Из рабочего файла я вытащу
всё сам: endpoint, имена полей, формат ответа, пиксели. Это точнее, чем ответы саппорта.

Если есть — приложи ещё и `call.html`/`error.html` (thank-you / redirect страницы).

---

## Путь 2: спросить у саппорта партнёрки

Если рабочего сэмпла нет — скопируй этот блок и отправь их саппорту/в чат, который заводит
офферы. Ответы пришли мне, и я интегрирую.

```
Нужно самостоятельно отправлять лиды (имя+телефон) с моего лендинга в вашу CRM. Подскажите:

1. URL (endpoint), куда слать заказ.
2. Метод (POST или GET) и формат тела (form-urlencoded или JSON)?
3. Точные имена полей в запросе для:
   - имя покупателя
   - телефон
   - id оффера (offer_id / product_id / …)
   - id вебмастера / потока (ref / wm / pp_id / stream …)
   - api-ключ / токен (и где он: в теле, в URL или в HTTP-заголовке — каком?)
   - гео/страна (если требуется)
   - субайди / клик- id (под какой параметр класть метку трекера, напр. sub1/click_id)
   - ip, referer/домен (если нужны)
4. Пример УСПЕШНОГО ответа (JSON) и ответа с ОШИБКОЙ. По какому полю понять,
   что заказ принят (result/status/success/…), и какое у него значение?
5. Где в ответе id заказа?
6. Редиректит ли ваш API сам, или я сам отправляю пользователя на call.html/error.html?
7. Нужен ли пиксель показа/лида (out-postback) — по какому URL его дёргать?
8. Мои ref (id вебмастера) и api_key для этой партнёрки.
```

---

## Что мне в итоге нужно, чтобы добавить партнёрку

Минимум (я подставлю в конструктор):

| Поле        | Что это                                                    |
|-------------|------------------------------------------------------------|
| `label`     | Название партнёрки (в выпадашке конструктора)              |
| `endpoint`  | URL приёма заказа                                           |
| `method`    | POST / GET, тело form-urlencoded или JSON                  |
| поля запроса| имена параметров: имя, телефон, offer_id, ref, api_key, субайди, гео |
| `okField` / `okValue` | по какому полю ответа и значению = успех         |
| `idField`   | где в ответе id заказа                                      |
| постбек     | нужен ли out-пиксель и его URL                             |
| `ref` / `api_key` | твои идентификаторы — закреплю за партнёркой (как у m1.top) |

## Как это выглядит после интеграции

В конструкторе появится новый пункт в списке «Партнёрка». `ref` и `api_key` будут
**закреплены** за ней (не вводишь руками), как сейчас у m1.top. Остальное (product_id,
язык, цена, фото) — как обычно.

> Большинство nutra-CRM (m1.top, everad, leadbit, adcombo, terraleads, dr.cash и т.п.)
> работают по одной схеме: POST имя+телефон+оффер+субайди → JSON-ответ. Отличаются в
> основном именами полей и endpoint — такие партнёрки добавляются за пару минут.
> Если у партнёрки принципиально другой поток (JSON-тело, токен в заголовке, свой
> редирект) — тоже добавлю, просто чуть больше правок в движок.
