# Универсальный drop-in заказа (`order.js`)

Один скрипт + один конфиг-блок, которые вставляются на **любой** лендинг
(любой дизайн, любой язык) и сразу дают рабочую отправку заявки в партнёрку
(m1.top), редиректы `call/error`, проброс трафик-параметров и определение IP.

Различается между лендами только **конфиг** (переменные). Сам `order.js` — общий.

---

## 1. Что вставить на ленд

В самом низу `<body>` (перед `</body>`):

```html
<!-- 1) конфиг оффера — МЕНЯЕТСЯ под каждый ленд -->
<script>
  window.OFFER = {
    product_id: 15058,                 // id оффера в партнёрке
    ref:        1029931,               // id вебмастера
    api_key:    '2188aad9cfb9f55626bf1d64cf4e95e0',
    langCode:   'be',                  // гео/язык для CRM
    success:    'call.html',           // редирект при успехе
    error:      'error.html',          // редирект при ошибке
    out:        true                   // out-пиксель m1.top (нужен m1ref.js)
  };
</script>

<!-- 2) зависимости партнёрки (как и раньше) -->
<script src="js/m1ref.js"></script>

<!-- 3) сам универсальный обработчик — ОДИН И ТОТ ЖЕ на всех лендах -->
<script src="order.js"></script>

<!-- 4) back-fix демонетизации (как и раньше, тоже drop-in) -->
<script src="js/ywbackfix.js"
        data-redirect="true"
        data-links='["https://nutrivition.top/VXsVxCX?sun={sub_id_30}"]'>
</script>
```

Всё. Больше на ленде трогать ничего не нужно — ни `$.ajax`, ни `sendData`,
ни хардкод product_id. Старые инлайн-скрипты отправки можно удалить.

---

## 2. Контракт разметки (одно требование к форме)

Скрипт сам найдёт форму и поля, если выполнено хотя бы одно из:

- у формы есть `data-order-form` **или** `id="order_form"`;
- поля названы `name="name"` и `name="phone"` (телефон можно и `type="tel"`).

Минимальный пример формы (стилизуй как угодно — на логику не влияет):

```html
<form data-order-form>
  <input name="name"  type="text" placeholder="Ваше имя" required>
  <input name="phone" type="tel"  placeholder="Телефон"  required>
  <button type="submit">Заказать</button>
</form>
```

Если разметку менять нельзя — можно указать селекторы вручную:

```js
window.OFFER = { /* ... */, formSelector: '#myForm' };
```
и/или пометить поля `data-order-name` / `data-order-phone`.

---

## 3. Что делает скрипт

- находит форму и поля (гибко, под любой дизайн);
- чистит ввод (имя — буквы, телефон — цифры), валидирует;
- POST в `m1.top/send_order` с `product_id / ref / api_key / langCode`;
- пробрасывает трафик-метки `s,w,t,p,m` и `subid`, определяет IP (ipapi.co);
- при `result:"ok"` → `success` + `?order_id=...&s=...`, иначе → `error`;
- подставляет имя/телефон из URL (для сундука после редиректа);
- опционально грузит out-пиксель m1.top (`out:true`, нужен `m1ref.js`).

## 4. Полный список полей конфига

| поле          | обяз. | по умолчанию            | назначение                              |
|---------------|:----:|-------------------------|-----------------------------------------|
| `product_id`  |  ✔   | —                       | id оффера                               |
| `ref`         |  ✔   | —                       | id вебмастера                           |
| `api_key`     |  ✔   | —                       | api-ключ вебмастера                     |
| `langCode`    |  ✔   | `''`                    | код гео/языка для CRM                   |
| `success`     |      | `call.html`             | редирект при успехе                     |
| `error`       |      | `error.html`            | редирект при ошибке                     |
| `out`         |      | `true`                  | грузить out-пиксель m1.top              |
| `api`         |      | `https://m1.top/send_order/` | эндпоинт партнёрки                 |
| `formSelector`|      | `[data-order-form]`     | ручной селектор формы                   |
| `subid`       |      | `''`                    | шаблон keitaro subid (напр. `{subid}`)  |
| `msgName`     |      | `Введите корректное имя!`| текст алерта (локализуй под гео)       |
| `msgPhone`    |      | `Введите корректный номер телефона!` | текст алерта                |

---

## 5. Ограничения / нюансы

- **`call.html` / `error.html`** должны лежать рядом с лендом (или укажи полные
  пути в `success`/`error`). Их дизайн — отдельно, к интеграции отношения не имеют.
- **`js/m1ref.js`** нужен только для out-пикселя (`out:true`). Без него всё
  остальное работает; поставь `out:false`, если не используешь.
- **`ywbackfix.js`** — отдельный drop-in (свой `data-links`), не часть `order.js`.
- **FB Pixel** оставляем как есть в `<head>` ленда (он и так уже drop-in через `{fbpx}`).
- Один и тот же блок работает и на **основном ленде**, и на **сундуке** — сундук
  просто дополнительно подхватывает имя/телефон из URL автоматически.
